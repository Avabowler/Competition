# 《未来战争》参赛程序

基于官方 Demo（CoreGeek）框架层重建的参赛 Bot，Python 3.11+ 纯标准库实现。

## 启动

```bash
bash run.sh <port>      # 判题器标准启动方式
python main3.py <port>  # 等价直调（与 Demo 同款入口）
```

## 架构（与 Demo/CoreGeek 同构：根目录 main3.py 入口 + src/agent 包）

```
main3.py          # 入口：解析 port、日志落盘、启动 HTTP 服务
src/agent/
├── server.py       # HTTP 层：3.5s 决策看门狗，异常兜底返回空指令
├── brain.py        # 总调度：昼夜编排、关门战术、LLM prompt 槽仲裁
├── protocol.py     # request 全字段解析 + 游戏常量表 + 指令构造器
├── validator.py    # 出站指令硬校验（防"异常响应"红线的最后防线）
├── memory.py       # 跨回合状态：LLM 预算/新闻归档/SOP 库/关门状态/炮台 loadout
├── grid.py         # A* 寻路（8 向、切比雪夫）
├── items.py        # 物品使用：应急炸弹/眩晕、药剂、召唤令、修墙（买→用闭环）
├── economy.py      # 采矿分工/贩卖/升级序列/券配送/回家 deadline
├── build.py        # 炮台位连通性选址 + 围墙防线 + 门口坐标
├── combat.py       # 夜战：锥形多目标/穿透/溅射叠弹、按站位格贪心配对
├── brain_baseline.py  # Demo 原版策略（A/B 回归基线，不参与正式决策）
└── tasks/
    ├── evolve.py   # 自进化任务：LLM 主导 + 多格式解析链 + 强制提交 + SOP
    ├── news.py     # 官方消息 → 矿价/停工预测（每日 3 次 LLM 预算）
    └── treasure.py # 民间传闻 → 宝藏三元组推理与召唤
```

### 关键设计

- **三层防出局**：validator 硬校验 → server 3.5s 看门狗 → 异常兜底。
  指令"执行失败"（碰撞等）不算异常，照常发送。
- **升级序列**（经济优先级）：急救升级（残血建筑用券回满血）→ 加特林L2 →
  火箭L2 → 基地L2 → 火箭L3 → 加特林L3 → 围墙券 → 电磁炮最后。
  火箭叠弹是对付大型/BOSS 的唯一高效输出故优先。
- **炮台选址**：连通性优先——三座塔的操控站位格必须从门口经内部走廊全部
  可达（BFS 验证），否则会出现第三座炮台永远无人可控的结构性死位。
  loadout（g/r/r 各一）按格子持久映射，建造失败连续 2 次才释放重排。
- **方向自适应防线**：机器人来袭方向由基地在地图左右半区推断（左半区基地 ->
  从东/远侧来，右半区 -> 从西来，真实环境校准过），围墙**正面排最优先建造**，
  门口开在背面（换边自动适配）；围墙修复/升级券目标也是正面墙优先。
- **墙优先调度**：围墙圈未合拢且缺口 >=8 时全员采石建墙（合拢一次后由石头工
  单维修，金属工回归采矿）；开拓者的自进化/宝藏任务在缺口 >8 时不出门，
  最迟白天第 40 回合放行（`WALLS_TASK_GATE` / `EVOLVE_FALLBACK_ROUND` 可调）。
- **关门战术**：黄昏 64 回合起全员归位（工人按"能否在 69 回合封门前到家"
  提前动身），69-70 封门；清晨 1-5 拆门；有人没回来就不关门。
- **物品闭环**：夜晚大怪逼近丢炸弹（8 回合冷却）、残墙 <30% 夜间抢修、
  血量 <100 嗑药、召唤令买了立刻用。
- **自进化任务稳健化**：LLM 输出按 JSON→bash 围栏→`$ 命令`→答案行 四级
  解析；连续失败转修正 prompt 再转兜底探索命令；超时 85% 强制提交拿部分分；
  SOP 全文一致才直接复用答案，仅签名一致则注入解法提示（防过期答案）。

## 测试与回归

```bash
python -m pytest tests/ -q                       # 37 项单测
python tools/mock_judger.py --days 10 --swap     # 模拟判题器 A/B（vs Demo 基线）
python tools/mock_judger.py --days 6 --hard      # 机器人波次 x2 压力测试
python tools/mock_judger.py --days 10 --llm-prose  # LLM 散文格式回复（解析兼容验证）
```

参考结果（seed 42）：A/B 双向 6812/8663 vs 60/61；--llm-prose 下任务线 6300 分
照常完成；异常响应 0；单回合决策均值 15ms / 最差 54ms（限额 5s）。

## 已知边界

- 可建造区域（蓝/黄）不在协议中，选址按"基地邻格/外圈 2 格"推断，
  建造失败自动跳过（不计异常，可安全试错）；关门格不可建则自动回退留门。
- 模拟器的机器人波次/行为是按任务书推断的近似，真实环境波次规模需线下校准。
